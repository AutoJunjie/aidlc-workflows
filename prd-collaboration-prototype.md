# AI-DLC 多人协作交互原型 PRD

> 产品需求文档 v1.0

---

## 一、背景与问题

### 1.1 现状痛点

在使用 AI-DLC 进行团队开发时，存在明显的协作瓶颈：

```
当前模式：
┌─────────────────────────────────────────────────────┐
│                    共享屏幕                          │
│  ┌─────────────────────────────────────────────┐   │
│  │          AI-DLC CLI / IDE                   │   │
│  │                                             │   │
│  │  Q: 您希望使用哪种数据库？                    │   │
│  │  A) MySQL  B) PostgreSQL  C) DynamoDB       │   │
│  │                                             │   │
│  │  [Answer]: _                                │   │
│  └─────────────────────────────────────────────┘   │
│                       ▲                            │
│         ┌─────────────┼─────────────┐              │
│         │             │             │              │
│      张三口述      李四口述      王五口述           │
│      "我觉得A"    "B更好吧"    "C适合我们"         │
│                       │                            │
│                       ▼                            │
│                   操作者输入                        │
│              （信息损失、效率低下）                  │
└─────────────────────────────────────────────────────┘
```

**核心问题**：
1. 只有一个人能输入，其他人只能口述
2. 意见容易被遗漏或误解
3. 讨论过程无记录，决策依据不清晰
4. 无法直观看到每个人的观点和倾向

### 1.2 目标用户

- **Tech Lead / 架构师**：主持讨论，做最终决策
- **开发工程师**：参与讨论，表达技术意见
- **产品经理**：参与需求澄清环节
- **团队规模**：4-6人

---

## 二、产品目标

### 2.1 核心目标

构建一个**多人实时协作界面**，让团队成员能够：
- 各自独立输入意见
- 实时看到他人观点
- 由Tech Lead汇总决策
- 结果无缝对接AI-DLC

### 2.2 设计原则

| 原则 | 说明 |
|------|------|
| **低门槛** | 打开浏览器即可使用，无需安装 |
| **实时同步** | 所有人看到相同的讨论状态 |
| **角色明确** | 主持人控节奏，决策者拍板 |
| **可追溯** | 每个决策都有讨论记录 |

### 3.2 功能模块详解

#### 模块A：房间系统

**A1. 创建房间**
- 输入：房间名称、我的昵称、选择角色（Tech Lead / 成员）
- 输出：生成6位房间码
- 规则：创建者默认为主持人

**A2. 加入房间**
- 输入：房间码、我的昵称
- 输出：进入协作界面
- 规则：最多6人，超出提示已满

**A3. 房间状态**
```
房间码: ABC123
参与者: 4/6
状态: 讨论中 - 问题 3/8
```

## 四、交互流程

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  1. 创建/加入房间                                           │

│  2. 等待参与者就位                                          │
│     │                                                       │

│     │                                                       │
│     ▼                                                       │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  4. 协作循环 (每个问题/审核项)                        │   │
│  │     │                                               │   │

│     │                                                       │

│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 关键交互细节

**场景：成员提交意见**
```
1. 成员点击选项按钮（如B）
2. 选项高亮，输入框激活
3. 成员输入理由（可选）
4. 点击"提交我的意见"
5. 卡片更新，显示选择和理由
6. 其他成员实时看到更新
7. 统计条自动更新
```

**场景：Tech Lead做决策**
```
1. 主持人点击"锁定讨论"
2. 所有成员输入区变为只读
3. 决策区对Tech Lead激活
4. Tech Lead查看统计和各方理由
5. 选择最终答案，填写决策理由
6. 点击"确认决策"
7. 决策同步到CLI，界面显示"已决策"
8. 主持人可点击"下一问题"继续
```

### 6.1 房间状态

```typescript
interface Room {
  id: string;              // 6位房间码
  name: string;            // 房间名称
  createdAt: Date;

  participants: Participant[];

  // 当前内容
  currentContent: QuestionContent | ReviewContent | null;

  // 讨论状态
  discussionState: 'open' | 'locked' | 'decided';

  // 历史记录
  decisions: Decision[];
}

interface Participant {
  id: string;
  name: string;
  role: 'tech_lead' | 'member';
  isHost: boolean;         // 是否主持人
  isOnline: boolean;
  joinedAt: Date;
}
```

### 6.2 意见与决策

```typescript
interface Opinion {
  odparticipantId: string;
  choice: string;          // 'A' | 'B' | 'C' | 'D' | 'X'
  reason: string;
  submittedAt: Date;
  updatedAt: Date;
  status: 'draft' | 'submitted';
}

interface Decision {
  questionId: string;
  choice: string;
  rationale: string;
  decidedBy: string;       // participantId of Tech Lead
  decidedAt: Date;
  opinions: Opinion[];     // 快照：决策时的所有意见
}
```

## 七、Demo原型技术方案

### 7.1 技术选型（纯前端）

| 技术 | 选择 | 理由 |
|------|------|------|
| 框架 | 纯HTML/CSS/JS | 零依赖，打开即用 |
| 样式 | 内联CSS | 单文件分发 |
| P2P通信 | PeerJS (WebRTC封装) | 无需后端，房间码连接 |
| 数据格式 | JSON | 标准化 |

### 7.2 原型范围

**包含**：
- 创建/加入房间
- 参与者列表实时更新
- 问题展示和意见输入
- 意见实时同步
- Tech Lead决策功能
- 主持人流程控制
- 模拟的AI内容（用于演示）

**不包含**：
- 真实的CLI集成
- 数据持久化
- 用户认证
- 设计审核模式（简化为问题模式）

### 7.3 文件结构

```
prototype/
├── index.html          # 首页：创建/加入房间
├── room.html           # 协作主界面
└── README.md           # 使用说明
```

## 八、验收标准

### 8.1 功能验收

| # | 功能点 | 验收标准 |
|---|--------|---------|
| 1 | 创建房间 | 输入信息后生成6位房间码 |
| 2 | 加入房间 | 输入房间码后进入协作界面 |
| 3 | 参与者同步 | 新成员加入，所有人列表更新 |
| 4 | 意见输入 | 选择选项+填写理由，点击提交 |
| 5 | 意见同步 | 提交后其他成员实时看到 |
| 6 | 统计更新 | 每次提交后，统计条自动更新 |
| 7 | 锁定讨论 | 主持人锁定后，成员无法修改 |
| 8 | 最终决策 | Tech Lead选择+理由，确认决策 |
| 9 | 切换问题 | 主持人可切换到下一个问题 |

### 8.2 体验验收

| # | 体验点 | 验收标准 |
|---|--------|---------|
| 1 | 响应速度 | 意见同步延迟 < 500ms |
| 2 | 状态可见 | 明确知道谁在输入、谁已提交 |
| 3 | 角色区分 | Tech Lead和成员看到不同的控件 |
| 4 | 流程清晰 | 知道当前在哪一步，下一步是什么 |
